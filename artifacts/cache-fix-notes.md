## 最终墙钟秒数

每行按冷轮、热轮 1、热轮 2 排列。

- 0 层：16.297 / 15.822 / 16.679 s。
- 1 层：15.611 / 7.399 / 7.513 s。
- 2 层：23.601 / 7.395 / 7.361 s。
- 随机两层：27.841 / 8.124 / 8.005 s。
- 同预算选择：27.492 / 8.225 / 7.921 s。

0 层每轮读源 payload 1.6 GB。缓存冷轮读源 1.6 GB，热轮为 0。每轮仍读取 252000 B header；marker 的文件访问未计入 pread 字节。热轮只读末层缓存 1.6 GB，上层缓存为 0。此次黄金缓存物理/消费读放大为 1。子范围校验可能读取完整段；专项测试验证该计数，不承诺所有布局均为 1。

源与缓存均执行真实 pread/pwrite。设备速度仍是模型：源 256 MiB/s、200 µs/op；缓存 4096 MiB/s、50 µs/op；NIC 4096 MiB/s。未清 OS page cache。计时包含计划、session、校验和模型延迟，不等于裸磁盘 benchmark。各 phase 秒数按 rank 求和，有重叠，不能相加解释墙钟。

## 热点与策略

热点定义为节点需求字节超过所在层均值的两倍。全覆盖 1 层热点为 0；全覆盖 2 层为 0/0。0 层没有缓存节点，缓存热点不适用。

随机两层使用 60/85 节点，热点为 6/0。同预算候选选择仍使用 60/85 节点，热点为 0/0。L0 最大需求从 64000008 B 降至 48000006 B。该收益来自节点集合选择，不改变 parent 的本机优先、其余轮转规则。仅比较四个固定候选，不承诺全局最优。计时没有证明策略显著更快。

## 代码修复

- 源 accessor 自动导出完整路径与 stat 身份。DCP 包含 .metadata。未知身份禁止跨调用采纳。
- 缓存 range 携带内部 source_identity。文件及 SSH 后端按身份隔离有效字节。
- 完整物理写入后才发布有效范围。零进展写明确报错。缓存 SHA256 检查在 consumer callback 前完成。
- 节点级锁替代全层文件 IO 锁。完整段查找直接命中；子范围仅查同节点同张量记录。
- 计划首进只构建一次。单计划复用存储 slot 映射。可变布局索引按内容失效。
- DCP session 延迟读取。只有实际 filler 触发 full load。它仍按 filler 全量加载，不承诺 DCP 冷读放大为 1。
- NIC 模型同时限制发送和接收。逐轮输出物理字节、消费字节、TX/RX、队列和文件分配。
- 执行器准入峰值检查 budget。持久有效文件容量与 active slot budget 分开记录；均不等于 RSS。

## 使用与边界

在 digest 的仓库根目录执行：

```bash
PYTHONPATH=. uv run --locked --extra torch-cpu python log/golden_chain.py
```

黄金同时调用双机控制。v100 必须支持现有 SSH 认证和 uv Python 3.12。双机控制自动部署并清理专用 helper，不启动常驻服务。

100 节点主测是 digest 单机 100 线程。另有 100 节点 file 协调器双轮小数据测试，不代表跨机 100 rank。双机控制为一个逻辑 rank，本机协调器和 SSH 数据后端。没有新增生产 peer 发现、RDMA 或跨机协调协议。

源身份使用 stat，检测通常文件变化，不证明恶意伪造 metadata 后仍安全。源在加载期间变化会返回 Err；不承诺回滚已写 destination。缓存重启后无索引则冷读。不承诺掉电恢复或持久索引恢复。
