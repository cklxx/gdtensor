6. DCP payload CRC 位腐：设计确认，非 bug

CONF-1 · 位腐静默加载是设计行为 非缺陷

  • 设计依据：README 明确「当前 IO 按 range 搬运字节，测试中的独立 oracle 执行数据校验」；设计文亦规定生产 IO 按 range 忠实搬字节，完整性是独立 oracle 的职责。
  • 测试依据：tests/checkpoint/test_checkpoint_merge_crc.py 先 corrupt_distcp_payload，断言独立 verify_crc 抛 AssertionError、读回值断言抛 AssertionError——不断言生产 rank_load 抛错；注释明示「repack must copy bytes faithfully」。
  • 本轮自证：在 704+4 翻一个字节（1.0 → 1.0000304），生产加载 raised=None，max_abs_diff=3.04e-5——与设计一致：生产成功、独立 oracle 抓到。.metadata 损坏则是 loud（unpickle 错误包成 GDTensorIOError），亦符合预期。
  • 结论：早前「P2-1 CRC 违反」重分类为覆盖注记。不存在「生产必须拒绝位腐 payload」的承诺；若产品未来要 load 侧防篡改，那是新需求而非 bug 修复。
